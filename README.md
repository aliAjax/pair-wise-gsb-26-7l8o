# hxwl-12 心理咨询个案测评与复测跟踪台

按量表版本录入条目，正反向计分生成总分与风险等级；高风险/升级强制登记联系计划；同一量表七天复测拦截；已完成测评冻结、更正生成新版本并完整保留原数据。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS，未新增任何运行时依赖（仅补 `@types/react` 类型声明到 devDependencies）。

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5112
npm run build    # 类型检查后产物构建
```

## 分层结构（领域数据 / 计算规则 / 界面分离）

```
src/
├── domain/            # 领域数据，纯数据无逻辑
│   ├── types.ts       # 个案、量表版本、测评、联系计划、规则冲突类型
│   └── scales.ts      # 量表目录：GAD-7 v1.0、PMH v1.0 / v2.0（条目、正反向、分项、风险区间）
├── rules/             # 计算规则，纯函数，不依赖 React/DOM
│   ├── scoring.ts     # 正/反向计分、分项分、总分、风险等级、升级判定
│   ├── retest.ts      # 七天复测间隔、剩余天数（UTC 日期相减）
│   └── submit.ts      # 整单校验：缺条目 / 复测过早 / 更正无原因 / 缺联系计划
├── state/             # 状态层（框架无关的发布订阅 + localStorage 持久化）
│   ├── seed.ts        # 演示数据（全部经规则函数计分生成）
│   └── store.ts       # 唯一变更入口；提交失败只落拒绝单，不写测评数据
└── ui/                # React 界面
    ├── AssessmentDesk.tsx  # 按版本录入、实时计分、强制联系计划、整单拒绝冲突表
    ├── CaseArchive.tsx     # 个案档案与冻结版本链（原条目/分项分/总分/风险等级留痕）
    ├── RetestBoard.tsx     # 复测提醒：个案 × 量表、前次日期、剩余天数
    ├── PlanBoard.tsx       # 联系计划、责任咨询师、完成时限、逾期标记
    └── Rejections.tsx      # 拒绝记录（个案、量表、原值、新值、触发规则）
```

## 业务规则

1. **按版本录入与计分**：选择「量表@版本」后按该版本条目作答；正向取原始分，反向取 `最大分 − 原始分`；实时汇总分项分、总分，按版本区间映射风险等级（稳定 / 关注 / 中风险 / 高风险）。
2. **强制联系计划**：总分达到高风险阈值，或风险等级较前次有效测评升级时，必须同时登记联系计划（方式内容）、责任咨询师、完成时限；任一缺失整单拒绝。
3. **七天复测拦截**：同一量表（跨版本同样适用）距上次有效测评不足 7 天提交即拒绝，冲突中列出个案、量表、前次日期、本次日期与剩余天数。更正沿用原测评日期，不受此限、不占用复测资格。
4. **冻结与更正**：测评完成即冻结不可编辑；更正必须填写原因，生成 r+1 新版本，原版本的条目作答、分项分、总分、风险等级全部保留并标记「已被新版本取代」。
5. **刷新一致**：个案、测评版本、联系计划、拒绝单均持久化到 localStorage，由同一状态源派生各视图；冲突统一以「个案 / 量表 / 字段 / 原值 / 新值 / 触发规则」表格展示。
